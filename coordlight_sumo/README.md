# CoordLight on SUMO

CoordLight (PyTorch + PPO multi-agent actor-critic + Ray) cannot be merged into the
TensorFlow + DQN pipeline of this repository without re-implementing it. Instead,
`cityflow_api_over_sumo.py` provides an engine with exactly the interface of
`cityflow.Engine`, implemented on TraCI, so that the original CoordLight code runs on
SUMO. Only 13 `self.eng.*` calls in `MATSC_CityFlow.py` touch the simulator; the QDSE
observation, neighbourhood reward and phase logic are unchanged.

| File | Purpose |
|---|---|
| `cityflow_api_over_sumo.py` | TraCI back end with the `cityflow.Engine` interface |
| `run_coordlight.py` | evaluates a trained CoordLight model on SUMO and exports the results in the layout read by `d2marl_sumo/collect_results.py` |
| `fix_net_config.py` | adds the missing `lane_length_dict` to CoordLight's New York net_config |
| `CoordLight/` | not included: clone and patch it as described in `baselines/coordlight/README.md` |

Two conventions differ between the simulators and are handled in the back end:

| | CityFlow | SUMO | Handling |
|---|---|---|---|
| Lane numbering | inner to outer, 0..N-1 | outer to inner | CityFlow-style ids are exposed; the index is reversed internally (N-1-k) |
| Vehicle position | `get_vehicle_distance` = distance travelled on the lane | `getLanePosition`, same meaning | used directly |

Phase mapping: `set_tl_phase(id, 0)` is yellow and `1..N` are the green phases, matching
the tlLogic layout (G0 Y0 G1 Y1 ...) generated by `d2marl_sumo/cityflow2sumo.py`.
Without `CL_SIMULATOR=sumo` CoordLight runs on CityFlow as before.
